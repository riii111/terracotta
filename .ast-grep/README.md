# Rust test rules

`ast-grep` 0.42.1 checks `src/**/*.rs`, `tests/**/*.rs`, and `examples/**/*.rs` for two test rules.

## Test module boundary

Put outer `#[cfg(...)]` attributes containing the `test` predicate on a module declaration, then keep test-only definitions inside that module.

Allowed:

```rust
#[cfg(test)]
mod tests {
    fn helper() {}
}
```

Rejected:

```rust
#[cfg(test)]
fn helper() {}
```

The rule recognizes `test` inside `all`, `any`, and `not`. It does not inspect `cfg_attr`, `cfg!`, inner `#![cfg(...)]` attributes, attributes generated by macros, or attributes containing only the `test-support` feature. It does not resolve modules across files. Fixes are manual because moving helpers can change visibility and dependencies.

## Named rstest cases

Name case declarations on functions with `#[case::name(...)]`. The `#[case]` marker on a function argument is valid rstest syntax and is allowed.

```rust
#[rstest]
#[case::up_arrow(Key::Up)]
fn maps(#[case] key: Key) {}
```

An unnamed `#[case(...)]` or `#[case]` on a function is rejected. The rule checks syntax only; whether a name explains the input remains a review decision.

From the repository root, run `ast-grep test --skip-snapshot-tests` to validate the rule cases, then `ast-grep scan` to check source files. The pre-commit hook runs the scan; install Lefthook and ast-grep 0.42.1 in your environment and enable the repository hook with `lefthook install`. The Nix devShell provides both tools. CI runs the rule tests and scan.

To extend a rule, edit its file in `.ast-grep/rules/`, add valid and invalid examples in the matching `.ast-grep/tests/` file, and rerun both commands. The rules report violations without automatic fixes.
