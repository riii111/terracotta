# Test module boundary

`ast-grep` 0.42.1 checks `src/**/*.rs`, `tests/**/*.rs`, and `examples/**/*.rs` for outer `#[cfg(...)]` attributes containing the `test` predicate. Put the condition on a module declaration, then keep test-only definitions inside that module.

Allowed:

```rust
#[cfg(test)]
mod tests {
    fn helper() {}
}
```

Rejected:

```rust
#[cfg(test)]
fn helper() {}
```

The rule recognizes `test` inside `all`, `any`, and `not`. It does not inspect `cfg_attr`, `cfg!`, inner `#![cfg(...)]` attributes, attributes generated by macros, or attributes containing only the `test-support` feature. It does not resolve modules across files. Fixes are manual because moving helpers can change visibility and dependencies.

From the repository root, run `ast-grep test --skip-snapshot-tests` to validate the rule cases, then `ast-grep scan` to check source files. The pre-commit hook runs the scan; install Lefthook and ast-grep 0.42.1 in your environment and enable the repository hook with `lefthook install`. The Nix devShell provides both tools. CI runs the rule tests and scan.

To extend the rule, edit `.ast-grep/rules/test-cfg-module-boundary.yml`, add valid and invalid examples in `.ast-grep/tests/test-cfg-module-boundary.yml`, and rerun both commands. The rule reports violations without automatic fixes.
